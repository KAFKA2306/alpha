# alpha

Research prototype for generating and evaluating neural-network architecture candidates for financial time-series experiments.

This repository contains exploratory code. The presence of an implementation, example, or historical result file is **not** evidence of live trading performance or production readiness.

## Current implementation

The current tree contains these main surfaces:

- `src/models/domain_blocks.py` — the default PyTorch domain-block registry. It currently registers 15 blocks.
- `src/agents/architecture_agent.py` — architecture-generation logic.
- `src/experiments/` — experiment and evaluation helpers.
- `examples/` and `experiments/` — research scripts and demonstrations.
- `mcp_servers/` — experimental data-server code with its own tests and requirements.
- `config/config.yaml` — research configuration.

The repository also contains generated block data and older research scripts. They are not treated as verified capabilities merely because they are tracked.

## Verified by CI

The repository CI runs the same `make check` command used locally. It:

1. compiles the tracked Python source,
2. runs the standard-library registry smoke test,
3. requires exactly 15 registered default blocks,
4. instantiates `layer_norm`, executes it on a tensor, and verifies the output shape,
5. requires a clean checkout after validation.

This is deliberately narrower than the complete research codebase. A green CI run does **not** verify architecture quality, backtest profitability, external data integrations, deployment, or monitoring.

## Not currently claimed as verified

The current repository does not provide runtime evidence for the following claims, so this README does not present them as completed capabilities:

- production deployment, rollback, or monitoring,
- a working FastAPI service from the current tree,
- live J-Quants integration,
- any particular Sharpe ratio, hit rate, maximum drawdown, or trading return,
- profitable or production-ready models generated by the architecture code,
- a fully reproducible fresh-clone environment for the complete dependency set.

The broad dependency declaration in `requirements.txt` is not locked. Consolidating dependency and quality-tool ownership remains tracked in [Issue #2](https://github.com/KAFKA2306/alpha/issues/2).

## Local verification

With Python 3.11, NumPy, and PyTorch installed:

```bash
make check
```

## Research boundary

Architecture generation and successful model construction are research outputs, not evidence of alpha, profitability, or future performance. Any financial evaluation must independently define its data provenance, train/validation/out-of-sample split, transaction-cost assumptions, leakage controls, seed, and evaluation period.

This repository is for research and educational use. It is not investment advice and does not provide a return guarantee.
